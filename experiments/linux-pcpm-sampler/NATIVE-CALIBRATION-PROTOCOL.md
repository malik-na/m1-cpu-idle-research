# Native PCPM calibration protocol (pre-acquisition)

This protocol addresses [issue #6](https://github.com/malik-na/m1-cpu-idle-research/issues/6) on a later native T8103 Linux boot. It was written before any PCPM read on this Mac. The corrected sampler has passed source and object checks; a new full Aurora link, installation, boot, and native capture are separate gates. The existing WFI D/E/C/B/A packets used a different image and do not calibrate PCPM.

## Hypothesis and boundary

The candidate is the complete 32-bit PCPM word at offset `0x48` in the main T8103 PMGR bank. Its numeric `ACTUAL = (raw >> 4) & 15` code may distinguish sustained P-core work from intervals in which all four P cores are in software `CPU PD`, and may return to the active reference on a controlled wake. The counterexample is a constant, unstable, inaccessible, or observer-sensitive word. A result can establish only a **PMGR-reported discriminator** under the tested conditions. Neither a software idle interval nor a PCPM code proves rail power state, energy savings, a transition instant, or that sampling did not suppress a physical transition.

## Boot and first-read gates

Keep stock Omarchy and the working WFI research image available. Before each run, verify the selected new `-wfi-pcpm` image, running release and GNU Build-ID, compressed configuration hash, patch/source/build receipts, same-boot FDT, eight online T8103 CPUs and E/P identities, both PMGR resources, cpuidle/cpufreq settings, module-package integrity, and the sampler/observer ABIs. Preserve the exact boot arguments and full identity packet privately. Record AC/battery, brightness, USB/network state, temperatures, background activity and firmware identity; hold AC connected and brightness at 155 for the first block. Let the machine settle after building or booting.

The first new-image acquisition is **records-only**. Launch APSC `records 9500` and PCPM `records 90 100 0` concurrently on a fresh boot. The PCPM command must establish the unique main PMGR node, existing internal clockless syscon map, E-core worker and physical-counter metadata, but makes zero PCPM register reads. Save both pre-command exports and complete post-command status, CSV, command stderr/exit status and timing even if qualification fails. One valid PCPM command consumes its one shot, including failure; do not retry on that boot or replace its packet. A later MMIO boot is permitted only after the first packet passes its identity, mapping, reader, schedule, overlap and loss checks. A successful source build alone does not pass this gate.

## Fixed workload and paired controls

Use four ordinary, unprivileged, independently schedulable workers pinned to the verified logical P CPUs, with the coordinator pinned to an E core. Schedule a common monotonic start `t0`; log each worker's actual CPU, phase boundaries, completed work and errors. Each 9-second window has these phases:

| Time from `t0` | P-core condition | Expected diagnostic role |
| --- | --- | --- |
| 0–2 s | All four P workers continuously active | Active reference |
| 2–4 s | One P worker active; three released | Cluster-level versus individual-core contrast |
| 4–7 s | All four workers released | Opportunity for overlapping software `CPU PD` |
| 7–9 s | All four resume controlled work | Return/wake reference |

The workload's intent does not authenticate actual idle: check the independent APSC records and loss counters. Launch the two blocking control writes in separate processes or threads near `t0 - 250 ms`, retaining their *actual* start and return times. APSC's 9.5-second window and PCPM's nominal 9-second schedule must overlap the observed workload phases; a nominal launch time alone does not establish this. Exclude a PCPM sample unless its full read bracket lies at least **300 ms** inside the measured phase boundaries. Preserve late, skipped, failed and out-of-phase rows.

After the records-only qualification, make a matched sparse-read run on a fresh boot with APSC `records 9500` and PCPM `mmio 90 100 0`. Keep the same workload and environment. If this is usable and suggests a discriminator, repeat with a predeclared cadence/phase change: `records 45 200 100` and `mmio 45 200 100` on separate fresh boots, with the same APSC capture and workload. A same-image APSC-records/no-PCPM run and an observer-unarmed workload run provide controls for the sampler timer/counter work and the APSC hook. Repeat or reverse controls if environment drift prevents a fair comparison. Each mode is one shot per boot; failed runs remain results.

For each paired run, perform the counter-qualification pre phase before either acquisition, allow the declared 5-second settling interval, and perform the post phase only after both exports have drained. Do not put cross-CPU qualification traffic inside either capture. Check each stream independently before pairing. The prior 240-tick cross-CPU error is an **assumption**, not a capture-wide measured bound; never silently upgrade it. For a conditional PCPM bracket inside all four P-core software intervals, first require the new boot's `CNTFRQ` to be 24 MHz, then use the strict inequalities in [JOINT-CAPTURE.md](JOINT-CAPTURE.md), predeclare `E=240` ticks and `G=24,000` ticks (1 ms), require complete zero-loss peer intervals and retain every excluded row. Report such pairing as conditional on the unverified `E` assumption. Coarse monotonic workload-phase contrasts do not require an exact WFI association.

Before inspecting MMIO codes, set the screening threshold at **at least five valid, fully phase-interior samples** in each of the all-active, all-workers-released and wake phases, on each of two MMIO boots. A candidate discriminator requires a distinct modal `ACTUAL` code in the released phase versus the active phase, each present in at least 80% of its usable samples, and return of the active modal code in at least 80% of wake samples on both boots. One-active results are retained separately. An all-P software-interval association additionally needs at least three valid fully contained samples per MMIO boot under the stated conditional clock model. These thresholds screen a signal under this protocol; they are not a physical-state or statistical non-invasiveness proof.

Compare APSC software-idle intervals, wake timing, lost records, sampler bracket latency, missed slots, and delivered work across no-PCPM, PCPM-records and PCPM-MMIO runs at matched cadence. Report effect sizes and environmental differences; if MMIO changes those observables materially, treat its state distribution as observer-sensitive. Constant or inconsistent codes, missing software overlap, insufficient usable samples, read stalls/errors, or counter/record loss are negative or inconclusive results for this candidate, not evidence that deeper states never occur. Preserve full raw words, including TARGET and sticky bits, without converting sparse sample counts into residency or energy.
