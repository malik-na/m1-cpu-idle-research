# Default-disabled PCPU PS3 built-in prototype

This [incremental patch](0001-t8103-ps3-per-core-offline-prototype.patch) applies to the exact Aurora ABI 3 source tree identified by the [ABI 3 source and linked-build packet](../../aurora-apsc-observer/abi3-prototype/README.md), not to pristine upstream Linux. Its SHA-256 is `fa1441ab91832c19d19963d7d25f81ffe35afbc9e8da62ec8ce76f2a7c99976d`; the added C file's SHA-256 is `855ef122b1ddebf10b6b54176ccbdf7e8d56f3557ab6b520864f33e6e610aa3d`. The patch adds one built-in Kconfig/Makefile entry and one C file. It does not change the APSC observer, cpuidle driver, DVFS writer, idle policy, or any #5 capture path.

`CONFIG_APPLE_PCPU_PS3_PROBE` defaults to `n`. Even if that option is enabled, the source's two MMIO build gates default to zero: the `mmio` control returns `-EOPNOTSUPP`, and the disabled object has no `regmap_read`, generic syscon-map construction, or direct MMIO-read symbol. A separate **offline-only** compile with both gates set to one checked that the dormant read path builds; that object was never linked into a boot image or loaded. The sole map lookup is the existing-only, clockless main-PMGR syscon accessor already in the pinned ABI 3 tree. The fixed 32-bit slots are PCPU0–3 at main-PMGR offsets `+0x20`, `+0x28`, `+0x30`, `+0x38`, plus PCPM `+0x48`; PMGR `+0x38` is unrelated to APSC `LAST_CHG_TIME +0x38`.

The prototype is one-shot, E-core-bound and preallocated. It accepts at most 12 rows and 60 reads, with a nominal duration no greater than 10 seconds. Each of five serial words per row has its own counter/time bracket, raw-value validity, errno and CPU identity; partial rows and missed slots remain exportable. A returned read whose completed bracket exceeds 1 ms stops further reads. A stalled MMIO read has no software timeout. The first prospective **active-P-only** pilot is limited by the [#6 protocol](../PCPU-PS3-PROTOCOL.md) to two rows and ten reads; a read-enabled image must enforce that smaller cap in a separately reviewed activation delta before live use.

The [prepared activation delta](0002-active-pilot-cap2.patch), SHA-256 `844560313961c97e1691f2255c70effdc17377248101cfec65b422b277c6e1f1`, changes only the built-in probe's source-enforced limit from 12 to **2** rows and its two read gates from zero to one. The resulting C file's expected SHA-256 is `c82f4ff83d6df44b37a78713d160c8c4c63cf9f1d20de3461070100f2f52720f`. It was statically reviewed against the first active-P-only, ten-attempt plan. This delta is **not** a live-read authorization on its own: a completed linked image, boot identity, a fresh records-only qualification and subsequent independent review are still required.

[Offline validation](offline-validation.json) of the frozen patch passed `git apply --check` against the retained ABI 3 source, confirmed that the patch's C bytes match the source hash above, compiled disabled and enabled C objects with the retained ABI 3 flags, and passed 21 actual-C parser boundary cases. A read-only 17-check retained-base and 24-check current-ABI3 identity preflight also passed; those checks did not use MMIO. The private objects, full source tree and boot identifiers are not published. **No new kernel was linked, installed or booted for this prototype, and no PCPU register was read.** The current ABI 3 boot cannot run this new built-in probe. Any future #6 image needs a distinct linked-build receipt, boot qualification, active-only gate and observer-effect controls before interpreting a PMGR code. A code change alone would not prove physical rail-off, residency or energy saving.
