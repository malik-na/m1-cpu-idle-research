# Cap-two PS3 private packaging result

The [read-enabled cap-two linked build](LINKED-ACTIVE-BUILD-RESULT.md) was prepared as a distinct module package, initramfs and UKI in private storage. The [sanitized packaging receipt](cap2-packaging-receipt.json) binds the artifacts to the linked-build receipt and the sealed private candidate inspection. The release is `7.1.12-ARCH-apsc-20261002-wfi-pcpm-abi3-ps3`; its proposed Limine title is `Aurora-APSC-research-pcpu-ps3`. No new module tree or EFI image was installed by this preparation.

The private inspection found the package's 1,867 modules and inventory consistent with the active linked build. It checked the UKI release, embedded Image and initramfs; the candidate initramfs had the same 1,333 unique paths as the working ABI 3 initramfs after substituting only the release name. All 90 embedded module files matched the active linked-build module hashes. The packaging helper labels its candidate receipt *unreviewed*; a separate read-only audit subsequently matched the reviewed build pins, all 1,867 packaged modules and 90 embedded modules against their linked-build hashes, UKI sections and normalized 1,333-path inventory. That audit qualifies artifact identity only. The sealed candidate receipt's SHA-256 is retained in the public receipt. The package, UKI, raw initramfs, full path/module manifests, build logs and boot command line remain private.

This is **artifact-preparation evidence only**. Installation, post-install readback and a successful boot need separate checks. The first live #6 boot would still require an active-P, records-only one-shot with zero MMIO reads, review of that packet, and a later fresh boot of the same image before the ten-attempt read pilot. Packaging does not demonstrate safe PCPU access during idle, a PMGR-reported state contrast, physical rail-off, residency, energy saving or a reason to change Linux idle policy. It adds no #5 observation or reboot.
