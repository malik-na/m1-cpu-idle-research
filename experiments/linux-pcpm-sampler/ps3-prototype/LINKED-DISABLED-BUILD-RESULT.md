# Default-disabled PS3 linked-build result

The frozen PS3 patch was applied to the pinned Aurora ABI 3 source, with `CONFIG_APPLE_PCPU_PS3_PROBE=y` and both hardware-read gates at zero. The first `Image modules dtbs` build process was interrupted during module metadata compilation; a second invocation with the same source, configuration, release and build environment completed the remaining targets with exit status 0. This is a successful **incremental completion**, not a clean rebuild. The [sanitized status](full-build-disabled-status.json) binds that sequence to the private build log hash.

The [linked receipt](linked-build-disabled-receipt.json) pins the source-tree and configuration hashes, Image SHA-256 `782ac9f2d492b36645c5f10cc7f21147ebb984d4100e8c0171caffc2f15e7d1a`, and vmlinux Build-ID `d99656b8a41f623108df884e3e31f4f78c795552`. Validation reconstructed the Image from vmlinux, matched its embedded configuration, found the probe's unique built-in initcall and exact object in the Apple SoC archive, and found no `regmap_read` in the disabled probe object. All 1,867 modules passed ELF section, release metadata and split-BTF checks; 111 Apple DTBs and every module are hash-listed in the receipt. The linked-proof suites' 27 synthetic cases passed.

This is build evidence for a default-disabled instrument. It does not show a successful boot, safe PCPU MMIO access, a PMGR code transition, `CPU PD` residency, physical rail-off or energy savings. The [separate cap-two activation delta](0002-active-pilot-cap2.patch) still needs its own linked-image and boot qualifications before a first read.
