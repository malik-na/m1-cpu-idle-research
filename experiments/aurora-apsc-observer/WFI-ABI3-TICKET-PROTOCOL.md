# Candidate final-entrant ticket experiment (pre-acquisition)

This is a proposed opt-in extension for [issue #5](https://github.com/malik-na/m1-cpu-idle-research/issues/5), written before a full ABI 3 image build or native capture. The accepted [ABI 2 block](WFI-ABI2-BLOCK-RESULT.md) observed four APSC BUSY words at a first-attempt pre-DSB read. Its only candidate final-core BUSY row depends on an unverified capture-wide cross-CPU counter error. A fresh ticket experiment would test **software** final-entrant ordering without that assumption; it would not establish BUSY at the later WFI instruction, peer physical sleep, or energy. This is a shared-atomic extension to the [chosen trace route](../../notes/linux-dvfs-wfi-trace-choice.md), which called for offline candidate reconstruction without a hot-path last-core counter. Tickets do not track idle membership, but their shared cacheline still needs a new observer-effect control. The latter [instruction-state gap](WFI-INSTRUCTION-BOUNDARY.md) remains a separate gate even after a positive ticket result.

## Instrument and falsifiable result

Use one 64-bit Normal-memory atomic counter per verified T8103 cluster. Every recorded idle-enter and idle-exit hook obtains a unique full-order ticket while retaining its CPU, token, sequence, counter bracket, error and commit state. A prepared first-attempt WFI slot obtains `ticket_pre` before and `ticket_post` after its single existing APSC command load, with intervening slot stores, mode selection, and reviewed full-system barriers that order the Normal-memory tickets around the Device read. The tickets bracket the read but are not instruction-adjacent to it. A ticket-only `wfi_clock` mode must do the same ticket, barrier, counter and publication work, omitting only the command load; `wfi_mmio` retains the raw command and validity. Capture-start and capture-stop sentinels use the same counter. The source must preserve the original power-control MSR, `dsb sy; wfi`, retry branch, single-read count, cpufreq SET path, and one-shot bounds. An ordinary shared atomic adds cacheline traffic in the idle path and is **not** a zero-effect observer.

A positive software candidate on cluster CPU `c` requires a committed first-attempt `wfi_mmio` row with valid raw BUSY bit 31 set and, for each of its three peers `p`, complete matching idle tokens and strictly ordered tickets:

`start < enter[p] < enter[c] < ticket_pre[c] < ticket_post[c] < exit[p] < stop`, and `ticket_post[c] < exit[c] < stop`.

Reject the row if any peer has a nested, missing or contradictory interval; a CPU/cluster mismatch; failed `cpu_pm_enter`; invalid command read; ticket zero/duplicate/gap; ring overflow or missing commit; start/stop ambiguity; or unreviewed binary ordering. Preserve rejected rows and exact reasons. The ticket order places the **read** inside three peers' recorded software idle callbacks and makes `c` the last recorded entrant. It does not place those peers at WFI, prove a physical cluster state, or identify which recorded SET caused BUSY. DVFS writer and target records remain required; cross-CPU SET-to-read causality is conditional unless a separately reviewed writer-side ordering instrument is added.

## Native gates and controls

Before installing or arming, pin the exact Aurora source revision and local patch/tree/config/Image/modules/DTB hashes; complete an enabled and disabled ARM64 build. Inspect linked instructions for the intended LSE atomic operations, barriers, one APSC load in MMIO mode, no load in ticket-only mode, original WFI/retry bytes, register preservation, slot offsets and commit ordering. Verify all eight live CPUs support the instruction and the booted release, GNU Build-ID, configuration, DT command resources, policies, fallback images and one-shot ABI. Keep stock and working WFI entries available. Source checks and a passing build alone are not native evidence.

Use fresh boots for an unarmed same-workload baseline, ticket-only `wfi_clock`, and ticket-plus-read `wfi_mmio`. Predeclare a bounded quiet interval and controlled same-cluster and remote-writer opportunities, with complete delivered-work, charger, brightness, policy, network/USB, thermal, log, probe-cost and loss records. Retain full raw streams, including negative windows and ambiguous SET order; compare ticket-only versus ticket-plus-read overhead and opportunity counts before interpreting absence. The historical ABI 2 D/E/C/B/A runs are context, not matched controls for the new shared atomic/barrier design. Do not silently reuse the ABI 2 assumed `E=240` ticks as a proven clock bound.

A single clean ticket-ordered BUSY row establishes a positive **pre-DSB software-candidate** observation under this instrument. A zero needs at least 20 candidate-specific, primary-lag (≤600-tick conservative SET-to-probe upper bound) paired opportunities **per cluster**, zero relevant loss, and a matched command-read sensitivity/control analysis before it can sensitively weaken the hypothesis; otherwise report underexposure. Count a primary-lag opportunity only for a same-CPU SET/probe pair or with separately qualified cross-CPU ordering and error; never infer remote timing from ticketed idle hooks alone. The 600-tick gate governs negative sensitivity and does not erase a positive BUSY read outside that stratum. No ABI 3 outcome by itself closes the latest exact-WFI criterion on issue #5. Closing that criterion additionally needs a calibrated BUSY-continuity/completion invariant or a qualified independent instruction-correlated command-state trace; the current [`LAST_CHG_TIME` audit](LAST-CHG-TIME-AUDIT.md) supplies neither.
