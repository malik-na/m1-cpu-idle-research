# Issue #5: present native instruction-state boundary

**Evidence decision, 4 October 2026. No new MMIO read, module load, reboot or idle-policy change was made for this note.** The current ABI 3 boot's release, Build-ID and configuration passed the [20-check read-only preflight](lct-prototype/live-readonly-validation.json). The completed [A/D/E result](ABI3-E-TICKET-RESULT.md) already supplies 18 strict software final-entrant witnesses with APSC BUSY set at a first-attempt **pre-DSB command read**. For six, every peer's observer idle-exit ticket follows the candidate's post-WFI idle-exit ticket. Those tickets do not locate a peer within its exit path, and no saved sample reads the command at WFI.

The missing inference is temporal as well as causal. A finite read before WFI and another after it cannot determine the bit at the instruction if BUSY may clear and reassert between reads. Two controller histories can have the same observed words and different WFI-time states; this is a logical ambiguity, **not** evidence that reassertion occurred. A bridge needs an independently validated same-command completion/continuity rule or a qualified instruction-correlated command-state observation. The [writer audit](WFI-WRITER-IDENTITY-AUDIT.md) also found a capture-start gap, so the latest matching recorded SET word is not a unique hardware-command identity.

The remaining routes were checked against that requirement:

| Route | Present finding | Missing gate |
|---|---|---|
| Move or repeat the `+0x20` command read | The [linked WFI audit](WFI-INSTRUCTION-BOUNDARY.md) places the read before the original `dsb sy; wfi`; a closer software read remains non-atomic. The [prospective BUSY-transition protocol](WFI-APSC-CMD-BUSY-CALIBRATION-PROTOCOL.md) could characterize sampled transitions but has no live-ready writer/sampler implementation. | Same-command continuity or simultaneous state observation. |
| Use APSC `LAST_CHG_TIME` at `+0x38` | The [source-pinned review](LAST-CHG-TIME-CALIBRATION-FEASIBILITY.md) found only an offset and 24 MHz comment, without a qualified read width, safety contract or completion edge. In the retained exact-build macOS [APSC access excerpt](../../notes/raw/driver-apsc-register-access.disasm), the generic 64-bit helper and saved callers do not show a `+0x38` access. The apparent `[x22,#0x38]` loads in the [idle excerpt](../../notes/raw/driver-pmgr-cpuidle.disasm) are 32-bit software-structure fields: `x22` came from the `CPUCore*` argument at `+0xaf0`, and the field is passed to PS-level-indicator methods. The full macOS kernelcache is not retained on the mounted Linux filesystems, so this is an excerpt-scoped negative search. | Independent T8103 width/read-safety and timestamp-to-BUSY command contract before any access. |
| Trap or externally debug WFI | [EL2 TWI](WFI-EL2-TRAP-FEASIBILITY.md) traps a guest WFI attempt instead of observing an executed native WFI. An external debug PC sampler yields a PC, not an atomic APSC value. [Linux's CoreSight CPU-debug guide](https://docs.kernel.org/trace/coresight/coresight-cpu-debug.html) warns that reading an unpowered debug block during idle can hang the bus; its workaround constrains idle. [Arm's external-debug guide](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/Armv8-A%20external%20debug.pdf?revision=90e162de-a42b-4f06-ac19-4ec6d652e369) says a debug event stops normal PE instruction execution. | A demonstrated T8103 facility that observes both the executed native WFI and command state without changing that path. |
| Use a completion interrupt or PMU event | The pinned [T8103 cpufreq DT nodes](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/arch/arm64/boot/dts/apple/t8103.dtsi#L554-L564) declare MMIO resources and no completion IRQ. The pinned [Apple M1 PMU driver's exposed event list](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/perf/apple_m1_cpu_pmu.c#L202-L210) names cycles and instructions, not WFI or DVFS completion. This is a source/configuration limit, not proof that the silicon has no other feature. | A validated, accessible timestamped completion or command-state event. |

**Decision:** keep [issue #5](https://github.com/malik-na/m1-cpu-idle-research/issues/5) open and preserve the stock and working research boot entries. The completed E one-shot will not be rearmed. No additional live pilot under the current helper can settle the exact-WFI criterion. **Do not reboot again for #5 unless a genuinely independent timing signal becomes available and its safety and instruction relationship are qualified.** A T8103 register contract without that bridge is preparatory, not a reboot gate. Shift experimental effort to [issue #6](https://github.com/malik-na/m1-cpu-idle-research/issues/6)'s physical-state calibration. Physical peer sleep, energy and any idle-policy change remain separate questions.
