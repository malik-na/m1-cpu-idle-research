# Prospective T8103 APSC command-BUSY transition calibration

**Prospective protocol only, 4 October 2026; NO-GO for a live run with the present helper. No new register access or capture has been made under this plan.** This is a separate, bounded calibration design for [issue #5](https://github.com/malik-na/m1-cpu-idle-research/issues/5) on a newly qualified T8103/J313 ABI 3 research boot. Its current-boot assumptions must be checked anew before any later run. It does not repeat or extend the consumed one-shot ABI 3 E capture. E already established 18 software final-entrant witnesses with BUSY bit 31 set at the [first-attempt pre-DSB read](ABI3-E-TICKET-RESULT.md). This plan asks a narrower question: under ordinary Linux cpufreq SETs, can an independent reader observe and bracket transitions of that **same, already-reviewed** command-register BUSY bit? The answer might identify a practical sampling cadence or disprove a simple writer-to-BUSY model. It cannot retrospectively put E's BUSY value at WFI or prove BUSY at any future exact WFI instruction.

The separately built default-disabled private prototype is **not** an implementation of this protocol. It offers at most one synchronous 64-read loop per cluster, has no SET-triggered remote sampler or 44-second block journal, and its 2,048-entry global trace can fill during the proposed schedule. Its kretprobe starts only after registration, misses requests that never reach the wrapper and cannot prove actual store CPU or hardware write acceptance; it does not hold a demonstrated driver-unbind lifetime guard or enforce opposite-cluster reader placement. It has never been loaded. A fresh reviewed implementation, with a proven writer start boundary and mapping lifetime, is required before a command-only live pilot. The unused `+0x38` register remains a separate no-go without independent width and read-safety evidence.

The [pinned Aurora driver](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/cpufreq/apple-soc-cpufreq.c#L25-L36) defines the 64-bit command register at cluster-resource offset `+0x20` and BUSY as bit 31. Its [T8103 SET path](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/cpufreq/apple-soc-cpufreq.c#L193-L273) polls the **previous** command clear, then submits a SET; the local [observer wrapper](0001-aurora-t8103-apsc-observer.patch#L257-L275) retains that original write. The live source/binary must be checked again rather than inferred from these links. The [writer audit](WFI-WRITER-IDENTITY-AUDIT.md) found that the ABI 3 observer's inactive branch performs an unrecorded write and its active branch has a start-side writer gap. Because E consumed the boot's one-shot, its stream cannot serve as this calibration's complete writer trace. `+0x38`, PCPM, undocumented offsets, and any direct MMIO write are outside this plan.

## Falsifiable observations and limits

For a cluster with a confirmed, fully bracketed ordinary driver SET and no other **recorded Linux** SET between the relevant brackets, the reader may observe `BUSY=0 → 1 → 0`. Preserve every 64-bit word, not just bit 31: a positive result is one or more actual BUSY transitions with ordered read brackets and writer records. A clear read after a preceding BUSY read bounds an observed fall between those reads; it does **not** timestamp the internal edge. An observed `1 → 0 → 1` with no intervening accounted Linux SET challenges a single monotonic BUSY pulse *under the recorded-writer model*; it could also expose an autonomous or uninstrumented writer. A change of command fields without an accounted SET is likewise a counterexample to complete causal attribution, not license to invent a writer.

No observed BUSY after confirmed SETs is a sampler-exposure result unless timing, cadence, loss and the number of eligible distinct-pstate SETs support a separately predeclared sensitivity claim. This pilot declares **no universal negative criterion**: arbitrarily short pulses can fall between reads. Finite, clean `1 → 0` observations cannot establish a minimum BUSY hold time, exclude a later clear/reassert, or prove a completion invariant. A read at `t_read` and the later executed WFI remain distinct observations even if the measured gap is small. This plan contains no WFI-path probe and makes no peer-sleep, physical power, energy, wake-latency or policy-benefit claim. The [instruction-boundary audit](WFI-INSTRUCTION-BOUNDARY.md) remains the governing limit.

## Qualification before any live run

1. Privately pin current boot ID and selected Limine entry; chip/board, release, GNU Build-ID, linked Image, module, configuration, source/patch tree and DTB hashes; all eight online CPUs; the two DT-derived cluster resources and their policy CPU masks; cpufreq governor and fast-switch state. Verify the running ABI 3 image and the preserved stock and PCPM fallback entries. Link the private same-boot E identity without publishing a boot ID. Recheck that the existing observer says `complete`/used; never try to rearm, reset, or treat its old events as new.
2. Review the proposed helper's source, built bytes and linked instructions **before** loading it. It may map only the two DT-qualified cpufreq resources while their driver lifetime is held, perform 64-bit reads only at `resource + 0x20`, bracket each read with ordered 24 MHz physical-counter samples, and use fixed preallocated buffers. It must neither write an APSC/PMGR register nor add a wait, lock, register read, or branch to the idle/WFI path. The only hardware SET writes are those the unmodified cpufreq driver makes for normal requests. Check the mapping lifetime, unbind/hotplug handling, all buffer bounds, teardown and access-fault behavior. A separate code review must confirm that the tracing mechanism captures **both** paths through the live observer wrapper, including its inactive branch, and exactly one actual SET write per captured successful call; a function name or source review alone is insufficient.
3. The existing one-shot ABI 3 DVFS stream is unavailable for this new interval. A new loss-counted, per-CPU writer trace must record **every wrapped Linux SET attempt on both policies**, with issuing CPU, target policy/cluster, raw submitted word, success/error, entry and return counter brackets, and a unique sequence. It must account for suppressed/no-write requests and poll failures separately. Instrumentation at the actual store from boot, or independently proved quiescence before attachment, is needed to exclude calls begun before trace registration; a quiet wait by itself is not that proof. Static and linked-code review must show that all normal Linux cpufreq writes on this boot pass the traced site. Trace recursion, unregistered CPUs, missed returns, ring overflow and reader-buffer loss must have explicit counters. An external privileged, firmware or controller-autonomous write is not thereby excluded; unexplained command changes make the affected interval unattributable. If a complete trace cannot be installed and verified on this boot, **stop without a calibration capture** rather than using E's zero-loss counts as a substitute.
4. Preflight AC online `1`, backlight setting `155`, stable CPU topology/policies, thermal-zone reading, battery, network/USB inventory, and current kernel log. These are comparability gates, not proof of constant conditions between snapshots. Recheck at every block endpoint and stop the block on AC loss, policy/topology change, thermal alarm/throttling, cpufreq timeout/transition failure, command access fault, or unexpected kernel error. Do not repeat a visual brightness test unless a display regression is reported. Do not alter governor, frequency limits, idle policy or boot entry for this pilot.

## Bounded same-boot schedule and writer-gap discipline

This is a **new prospective pilot**, not a continuation of A/D/E. Use one target cluster at a time, with the reader pinned to a CPU in the other cluster; retain the actual reader CPU and any migration. For each target, run (i) one 10-second trace-only control with the pinned 200-pulse, 50-ms-spaced workload on a target-cluster CPU, (ii) one 2-second sampled quiet interval without scheduled pulses, and (iii) one 10-second trace-plus-reader block with the same workload. Cap the entire pilot at two clusters, six blocks, 44 seconds of block time, **32,768 command-read attempts per target cluster**, and **200 SET-triggered read bursts per target**. The helper samples at a declared 1-kHz base cadence and, after detecting a traced SET, may make at most 64 additional reads in a bounded burst on the opposite CPU; it never waits for BUSY to change. If actual scheduling delays a burst, keep the delayed samples with their timestamps rather than calling them immediate. Exceeding a cap stops new reads, increments a cap counter, and leaves the block unsuitable for a negative inference. No same-boot WFI E recapture is attempted. If normal schedutil activity yields few distinct-state SETs, record underexposure; do not force a governor or MMIO command.

The new writer trace must be attached and recording **before** each block's start marker, with the pre-registration gap already excluded by the preceding gate. Drain all pre-marker in-flight traced calls, with an explicit completion/grace-period proof, then mark the interior start; reject any call whose entry or return could straddle that marker. Keep tracing through the stop marker and drain all in-flight calls **before** detaching; reject straddling calls from the interior analysis. The current ABI 3 code's `capture_active` start marker is not such a proof. Both cluster traces must remain active even when only one command resource is being read, because the issuing CPU may be outside the target policy. Record the number of trace entries, exits, no-writes, successful writes, dropped/reserved/committed rows, unread rows, gaps and pre/post-drain calls. Accept an interval for writer-relative timing only when all relevant records are complete, no cross-boundary call is possible, and a separately justified conservative cross-CPU counter-error bound makes the brackets nonoverlapping. An empirical counter-exchange envelope alone does not guarantee a worst-case bound. Do not reuse the ABI 2 assumed 240-tick bound or infer remote order from ABI 3 idle tickets. If that bound is unavailable, retain raw order as ambiguous and still report each valid BUSY read at its own sample point.

Each read row must retain cluster/resource identity, reader CPU, sample and burst identifiers, requested versus actual cadence, raw 64-bit command, bit-31 decode, counter-before/counter-after, local sequence, success/error and buffer status. Each worker row must retain scheduled and actual times, CPU, completion and checksum. Capture block start/stop ticks and `CLOCK_MONOTONIC` markers, the independent counter-exchange measurements and their error model, status before/after, reader and trace attempt/commit/loss counters, complete kernel-log diff, and AC/brightness/thermal/policy/network/USB endpoints. Bound all private files with a SHA-256 manifest and exact helper/source/build hashes. Publish only a whitelist-based projection with normalized time origins, numerical words, brackets, gaps, controls and rejected rows, plus a private-to-public hash receipt. Keep full logs, boot IDs, machine/network identifiers, full boot arguments, credentials, local paths and absolute wall-clock markers private under [PROVENANCE.md](../../PROVENANCE.md).

## Analysis and stop decision

Reconstruct each cluster's successful SET and raw `0/1` sample stream from the sealed rows. Group a SET-to-read relation only when writer entry/exit and read brackets are strictly ordered after the measured cross-CPU uncertainty, no other **accounted Linux** SET overlaps, and no loss/start/stop gap applies. Keep all ambiguous and rejected intervals with exact reasons. Report, separately for both clusters, the number of distinct-state SETs, no-write requests, read attempts/completions, BUSY-high and clear words, observed `0→1` and `1→0` pairs, writer-to-first-high and last-high-to-first-clear **brackets**, and the fraction of SETs with actual sampled coverage in each lag stratum. Do not turn a sampling interval into an exact transition time or a same-word repeat into a hardware command identity. Compare completed workload, SET mix, scheduler activity, sample cost and thermal endpoints between trace-only and reader-active blocks; these different windows cannot isolate a causal reader effect by themselves.

Stop after this pilot. If a clean BUSY pulse is seen, publish its bounded transition observation and any contradictory intervals; do not assert a global continuity rule. If no pulse is seen, report the actual exposure and sampling limit. If loss, unexplained word changes, mapping uncertainty, an access error, unstable environment or an unqualified trace/clock bridge occurs, preserve the raw packet privately and mark the affected result inconclusive. Any later attempt to connect command state to an exact WFI execution needs a **separate protocol and independent temporal or instruction-correlated observation**; this calibration alone cannot close that part of issue #5.
