# ABI 3 writer identity is bounded to the observed driver path

**Static audit and replay of the public E packet, 4 October 2026.** The target is the T8103/J313 `7.1.12-ARCH-apsc-20261002-wfi-pcpm-abi3` build identified in the [E result](ABI3-E-TICKET-RESULT.md). The [ABI 3 source receipt](abi3-prototype/README.md) and [linked-build receipt](abi3-prototype/linked-build-receipt.json) identify the instrumented tree and binary. This audit performed no new capture or register access. It tests whether the E stream identifies the SET responsible for a BUSY-positive pre-WFI read; it does not reinterpret that read as the later WFI-instruction state.

The [pinned Aurora Apple cpufreq driver](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/cpufreq/apple-soc-cpufreq.c#L193-L273) has one ordinary Linux T8103 SET path: `apple_soc_cpufreq_set_target()` polls the **previous** command's BUSY bit clear, prepares a pstate plus SET-bit command, writes it once and returns without polling this new command to completion. Both its fast and slow callbacks converge on that path; the [observer integration patch](0001-aurora-t8103-apsc-observer.patch#L23-L56) routes that write through `apple_apsc_observer_dvfs_write()`. The [wrapper](0001-aurora-t8103-apsc-observer.patch#L218-L275) retains writer CPU, policy representative/mask, requested pstate, prior read, submitted word and counter brackets **when its active branch is taken**. The [cpufreq core contract](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/cpufreq/cpufreq.c#L2176-L2222) excludes parallel fast-switch callbacks for one policy; shared-policy [schedutil takes `update_lock`](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/kernel/sched/cpufreq_schedutil.c#L515-L542). The driver permits a request from another CPU (`dvfs_possible_from_any_cpu = true` in its initialization), so a candidate CPU's own recent SET is not necessarily the only cluster writer.

The [public E status](native-evidence/abi3-E/apsc-status-after.txt) reports fast switch enabled for both policies and DVFS attempts equal commits: 1,483/1,483 for cluster 0 and 213/213 for cluster 1, with zero overflow or missing commit. The [byte-exact public streams and validator report](native-evidence/abi3-E/README.md) retain 18 strict software final-entrant BUSY witnesses. For each witness, selecting the successful cluster-1 DVFS row with the latest `t1` below the WFI read's `t0` under raw counter ordering finds a same-CPU writer; its submitted word, with SET bit 25 removed, equals the witness's BUSY word with BUSY bit 31 removed. For example, CPU 4/token 177 has DVFS row 107 at ticks 5368447688–5368447689 (`0x40002104104`) and a pre-DSB read at 5368447736–5368447742 (`0x40080104104`). This is descriptive consistency, **not** a causal pairing: a capture-wide cross-CPU counter error bound is unqualified, target-state words repeat, and the published fields have no independently decoded hardware command sequence number.

There is also a source-visible capture-start gap. The [wrapper's inactive branch](0001-aurora-t8103-apsc-observer.patch#L257-L275) tests `capture_active` **before** issuing its unrecorded write. The [ABI 3 capture path](abi3-prototype/0001-abi3-cluster-tickets.patch#L141-L157) sets `capture_active = true` and then records `inside_start_ns`; it has a stop-side `synchronize_rcu()` but no start-side grace period between activation and the interior marker. A writer that read `false` just before activation could, in principle, perform its unrecorded write after the marker. The source establishes this possible interleaving, not that it occurred in E. Zero stream loss therefore covers entries that chose the active recording branch; it does not certify every physical SET during the whole interior. The idle/WFI cluster tickets order those recorded hooks and the command read, not DVFS writes from other CPUs.

A future command-identity claim needs a qualified start-side exclusion of pre-activation writers, a per-cluster order connecting **every** wrapped SET to read brackets, no stream loss, and a bound on cross-CPU counter comparison. It must separately address any uninstrumented privileged or firmware writer and controller-autonomous register change; this audit found no evidence that one acted during E, but the Linux wrapper cannot exclude them. A proposed `LAST_CHG_TIME` bridge additionally needs validated read safety, width/wrap, update edge and relation to **the same** BUSY command, including repeated equal-pstate requests. It fails if a timestamp changes without a recorded SET, does not change on a completed distinct transition, aliases separate completions, or if an unaccounted write or clear/reassert can intervene. Even successful writer attribution would still need an independent temporal bridge from E's pre-DSB read to the executed WFI instruction.
