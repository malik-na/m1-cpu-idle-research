# Offline prototype review and disposition

**4 October 2026; source SHA-256 `c5b9b8edc8cb2a9969d655a71bf891ece2e5cd447c605983cbc8f9833fd9d587`.** A separate code-review pass examined the default-disabled source, compiled module, design and preflight. It was a static/offline review; no module was loaded and no APSC register was read.

The first revision had a mapping error: an early exit while walking a later CPU could inherit a prior success return and leave one cluster base unmapped. The final source resets the error before each CPU's early exits and requires both mappings before success. The first revision also allowed the SET-slot counter to grow beyond the fixed array and checked counter ordering only within individual reads. The final source uses a saturating compare-and-swap allocator, checks command/last/status and row-to-row order, and rejects a row outside its capture window. The reviewer rechecked those corrections in the exact final source and found no critical issue blocking **publication of the disabled prototype**.

The [saved offline preflight result](offline-validation.json) passed 16/16 read-only checks, including source/module hashes, ABI 3 image/configuration/Build-ID, zero compile-time hardware gates and absence of mapping/kretprobe dependencies in the disabled module. A later [current-boot read-only run](live-readonly-validation.json) passed 20/20, adding live release, Build-ID and configuration checks. Neither result shows that an enabled build is safe. In particular, `+0x38` has no qualified T8103 access width or read-safety basis; this prototype's dormant command-only branch does not meet the [prospective pilot](../WFI-APSC-CMD-BUSY-CALIBRATION-PROTOCOL.md)'s complete writer/start-boundary, remote-sampling or bounded-block requirements. The final disposition is **no live load and no new capture**. A new enabled build needs its own code/linked-object review, current-boot checks and separate trial protocol; a `+0x38` build also needs a qualified width and read-safety contract.
