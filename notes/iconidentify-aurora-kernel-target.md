# Exact planned target: iconidentify/aurora-linux

Read-only provenance audit, 2 October 2026. The operator chose this repository's latest-release installer for the planned Omarchy kernel. No installed or booted kernel is identified by that choice; the floating entry point must be resolved again at installation time. This is a different repository from the previously inspected `aurora-silicon/linux`; retain the [earlier baseline](../wiki/Linux-and-Aurora-Baseline.md) under its original identity.

## What the installer actually selects

At the pinned revision, executable constants set `VERSION=7.1.12.aurora2-11.17` and `TAG=sep-7.1.12.aurora2-11.18`. The package names are `linux-aurora` and `linux-aurora-headers`; their archive names contain the former version. Companion packages are `m1n1-aurora`, `aurora-touchid` and `libfprint`. A differing release suffix and kernel-package suffix is intentional here: the release commit changes Touch ID userspace while preserving the kernel. [Constants and checksums](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/tools/aurora-sep/install-aurora-sep.sh#L43-L60), [release commit](https://github.com/iconidentify/aurora-linux/commit/90a95335a49aec3a0045a76da140452ad6585eb3).

The entry URL containing `releases/latest` is floating. Once a particular script is obtained, its package URLs use its own fixed tag and the code checks explicit SHA-256 values before package installation. The kernel archive's declared SHA-256 is `47a0ff9f8c8fc00edd3485668e0c71cc6d43a846d2dbf7abb160fbe2f833704e`. These are download/install recipes, not a reproducible kernel build recipe: the inspected script downloads existing packages and invokes pacman. [Fixed URL construction](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/tools/aurora-sep/install-aurora-sep.sh#L43-L58), [download, verification and package installation](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/tools/aurora-sep/install-aurora-sep.sh#L411-L443).

The full kernel PKGBUILD, its source URL/ref expression, and any package-build overlays were not recovered in this source inspection. The visible `tools/aurora-sep/aurora-touchid/PKGBUILD` builds Touch ID support, not the kernel. Do not promote the installer's source-comment attribution into a verified source-to-binary chain. The independently inspected package records a PKGBUILD hash, but reconstructing that exact recipe and its source/patch inputs remains unresolved.

The kernel archive was independently downloaded and hash-checked as data. Its metadata says `linux-aurora 7.1.12.aurora2-11.17`, and the image is stored under module release `7.1.12-2-11.17-sep-ARCH`. The image SHA-256 is `1d08d4153742e26d7012031452db79fe500cf376a84b07261fba59f97bf945e2`; its embedded configuration SHA-256 is `84bb71434e905f3b1360142e075a89b0bccb5e5bd7ca82eb892a362512df260e`. These establish a downloadable artifact's identity, not the kernel booted on the Mac. [Sanitized artifact receipt](raw/iconidentify-aurora-release-11.18.json).

## Consequences for the idle experiments

The actual archive's embedded config has `ARM_APPLE_CPUIDLE=y`, `ARM_APPLE_SOC_CPUFREQ=y`, `APPLE_PMGR_PWRSTATE=y`, `MFD_SYSCON=y`, `DEBUG_FS=y` and `IKCONFIG_PROC=y`. All three research instrumentation options are absent. `FTRACE=y` does not supply function tracing here: `FUNCTION_TRACER` is unset. The source [asahi.config](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/arch/arm64/configs/asahi.config#L1-L9) instead declares cpufreq as a module, demonstrating why source fragments cannot substitute for the artifact's final configuration. The built-in cpufreq prerequisite of the prepared [APSC observer](../experiments/linux-apsc-observer/README.md) is present in this archive, but patch compatibility and native behavior remain unqualified. [Artifact/config receipt](raw/iconidentify-aurora-release-11.18.json).

The release's cpufreq source includes optional post-write transition verification. The [T8103 initializer](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/cpufreq/apple-soc-cpufreq.c#L93-L100) leaves that option unset, whereas T8140 enables it. The [post-write poll](https://github.com/iconidentify/aurora-linux/blob/90a95335a49aec3a0045a76da140452ad6585eb3/drivers/cpufreq/apple-soc-cpufreq.c#L239-L253) is conditional on that option. This is a source-scoped T8103 result, not evidence of a new last-core wait on the user's machine.

All three research patches still pin [Asahi `77cb8f24…`](https://github.com/AsahiLinux/linux/tree/77cb8f24c2381a8abb7272d7bbdec548d6426a8a). Compatibility with this repository's default commit does not establish compatibility with its custom release. Qualify the actual cpuidle/cpufreq code, DT resources, timer configuration and syscon/regmap ownership; review and rebuild any port against the selected source and final config before authorizing an instrumented boot. Existing object-build checks supply no native-runtime result for this release.

The parallel source audit compared 20 relevant paths at `90a95335…` and `e11a8bc7…`: all matched. Read-only `git apply --check` against a directory populated with those 20 exact release-source files failed for the APSC observer at `drivers/cpufreq/apple-soc-cpufreq.c:174` and for counter qualification at `drivers/soc/apple/Makefile:25`; PCPM's patch passed that textual check. This establishes that two patches need adaptation and one finds its expected context. It does not validate compilation, semantics or runtime compatibility for any patch. [Source hashes and patch-check receipt](raw/iconidentify-aurora-source-comparison.json).
